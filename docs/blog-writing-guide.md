# 博客文章写作与排版规范

> 本文档为个人博客（Astro + Starlight）文章创作的**唯一权威规范**，统合了文章的技术排版约束与个人写作风格指纹。无论是人类作者还是 AI 编写，均需严格遵循本文档，确保全站风格统一、排版协调、构建不报错。

---

## 一、文章分类与风格指纹

本博客文章主要分为两类：**技术教程类** 与 **游戏评测类（长评）**。两类文章各有一套经过实践沉淀的风格指纹：

| 风格维度 | 教程类文章规范 | 游戏评测类文章（长评）规范 |
|---|---|---|
| **段落前缀** | 普通段落，步骤用 `1. 2. 3.` 编号列表 | **强制段落开头使用 `\- `（反斜杠+减号+空格）** 形成条目感 |
| **H1 开篇** | 亲切的 hook 句（如“把一首歌拆成伴奏和人声，其实没那么难”） | 煽情/感染力的 hook 句（如“20年的传承，音游类别中的永恒经典”） |
| **H2 结构** | 步骤编号格式：`## 1/4：克隆代码仓库`（**分母必须等于实际步骤数**） | 主题-副标题格式：`## 游戏难度 - 整个一周目就是一个巨大的教程` |
| **段落长度** | 2-4 句话一段，**绝不出现超过 5 句话的大段** | 1-3 句话一段，配合 `\- ` 保持节奏紧凑 |
| **文末收束** | “善后工作/踩坑排查”大节 + 固定致谢段落 | “结语”大节（价格/SteamDB链接 + **“献给xx的你”** 专属致谢） |

## 二、Frontmatter 规范（核心铁律）

### 1. 通用基线：极简 3 字段铁律

**普通文章严格统一为 3 个字段，不多不少：**

```yaml
---
title: "文章标题"            # ✅ 必填，页面正式标题（用于侧边栏与 SEO）
description: "一句话简短描述"  # ✅ 必填，建议 60-150 字（用于搜索与卡片描述）
pubDate: "2026-08-15"       # ✅ 必填，发布日期，严格双引号包裹的 "YYYY-MM-DD"
---
```

- **严禁随意添加** `author`、`tags`、`slug`、`draft`、`heroImage` 等无关字段。
- **title 必须提供**，否则构建阶段将触发 `[InvalidContentEntryDataError] title: Required` 报错。
- **关键区分**：frontmatter 的 `title` 是客观正式的页面名，**正文首个 `#` (H1) 是具有感染力的 hook 句**，二者不应简单复制重复。

### 2. 受控白名单特例：游戏长评 (Deep Review)

仅当编写**游戏长评**且需要顶部视觉海报横幅时，允许扩展以下受控字段：

```yaml
---
title: "DJMAX RESPECT V：20年的传承与经典"
description: "二十年音游传承，PC 上最完善的下落式音游体验全景评测。"
pubDate: "2026-08-15"
sidebar:
  badge: "评测"              # 侧边栏徽章标记
hero:
  title: "DJMAX RESPECT V"  # 游戏官方名
  tagline: "20年的传承，音游类别中的永恒经典" # 评测副标题/评分总结
---
```

*注：`minutesRead` 与 `words` 会由 `remark-reading-time` 插件在构建期自动计算注入，不需要手写。*

## 三、排版与视觉格式细节

### 1. 文件命名 (Slug)
- 存放在 `src/content/docs/blog/` 目录下。
- **绝对禁止使用空格和 `+` 号**。
- 普通文章使用有意义的中文或小写中划线（如 `如何安装msst音乐音源分离工作流.md`）。
- 游戏长评推荐使用英文 slug + 下划线（如 `djmax_review.md`），必须与画廊注释文件 `src/data/steam_annotations.json` 中的 `blog_url`（如 `/blog/djmax_review`）严格一致。

### 2. 分隔线 (`---`)
- **高频使用水平分隔线**：在每个 `##` (H2) 标题之后通常跟随一条 `---` 分割线，制造呼吸感与明晰的区块划分。

### 3. 粗体 (`**`) 与斜体 (`*`)
- **粗体为最核心的强调手段**：不仅对专有名词加粗，凡是希望读者留意的核心观点、否定词（**不**含、**请勿**）、程度副词（**唯一**、**高达66GB**）及重要补充说明均需加粗。
- **斜体克制使用**：仅用于游戏内部机制术语（如 `*逆转*`、`*文字显示速度*`）或特殊强调。

### 4. Emoji 纪律
- **正文内原则上严禁滥用 Emoji 表情**（仅允许终端代码注释箭头 `➡️` 或偶尔纯字符颜表情如 `(•̀_•́)7`）。侧边栏分类已有图标，文章正文保持干净专业。

### 5. 换行与代码块
- 本项目启用了 `remark-breaks` 插件，Markdown 内**单次回车即渲染为换行**。
- 代码块需标明语言（如 `bash`、`typescript`、`json`），代码内注释采用中文。

pubDate: "2026-08-15"
---

# 一句话亲切的开篇 H1

---

> 开篇导语或背景介绍。

这里我默认你已经对 **命令行** 以及 **基础环境** 有了一定的认知。

## 1/3：准备运行环境

```bash
# 执行环境配置

```

## 2/3：核心模型下载

---

核心步骤说明...

## 3/3：执行并验证

---

运行结果与验证。

---

常见报错与排查清单。

本站基于开源框架 **Astro** 与 **Starlight** 搭建，托管于 **GitHub Pages**。在此特别感谢相关技术栈支持。

```markdown

  badge: "评测"
hero:
  title: "只狼：影逝二度"
  tagline: "打铁还需自身硬，生死之间见真章"

---

\- 如果你是动作游戏爱好者，那么你一定听说过“打铁”的魔力。

\- 敌我双方的生命值退居二线，真正决定生死的是那根摇摇欲坠的架势槽。

## 结语

---

\- 推荐购买：Steam 原价 268￥ / 史低 134￥，极力推荐入库。

\- 这篇评测献给 **想要在每一次刀刃相接中找寻专注与突破的有着武侠与动作梦的你**。

## 五、发布前自查清单 (Pre-flight Checklist)

- [ ] **Frontmatter 格式**：严格使用包含 `title`, `description`, `pubDate`（`YYYY-MM-DD`）的极简 3 字段；非长评绝不包含多余字段。
- [ ] **标题区分**：正文 H1 是抓人眼球的 hook 句，未照抄 frontmatter 的 `title`。
- [ ] **格式指纹**：
  - 教程类：步骤标号为 `N/M` 且分母真实准确；
  - 评测类：正文各主要段落均带有 `\- ` 前缀。
- [ ] **视觉标记**：每个 H2 下方均有 `---` 分隔线；正文无杂乱 Emoji；重要概念已加粗。
- [ ] **链接闭环**（仅长评）：
  - 检查文章文件名与 `src/data/steam_annotations.json` 中的 `blog_url` 保持一致；
  - 检查 `astro.config.mjs` 中的「游戏评测」嵌套组已录入该文章 slug。
- [ ] **本地验证**：运行 `npm test` 通过，`npx astro check` 0 errors，`npm run build` 构建成功。
